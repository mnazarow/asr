# Известные ограничения

Эта глава ведётся, а не дописывается: в ней то, чего ASR Hub **сейчас** не делает или что не проверено, — коротко и с обходным путём. Сделанное уходит отсюда в журнал изменений (`CHANGELOG.md` в корне проекта); планы и оценки объёма — в главе [33. Что доделать и улучшить](33-roadmap.md).

Состояние на версию 3.1.32.

## Не проверено на живом оборудовании

| Что | Чем проверено | Что это значит на деле |
|---|---|---|
| Asterisk 16–22 и FreePBX 16–17 с настоящим транком | подменные станции в тестах: AMI (в том числе TLS и вход по MD5), журнал CDR, `queue_log`, диалплан, SIP-телефон контроля качества | первую станцию подключайте с разделом «АТС» → «Разбор» и суточной сверкой «станция ↔ архив»: она покажет потери в первые же сутки |
| Раздельные дорожки `MixMonitor(…,r()t())` | сценарий отправки и приём двух файлов — в тестах; сам диалплан — по документации Asterisk | проверьте одной пробной станцией: в карточке звонка запись должна быть стерео |
| Установка и клиент для Windows (PowerShell) | разбор сценариев и проверки по тексту | установка на Windows Server — с присмотром; `-Pinned` повторяет `--pinned` из bash |
| Сборка образа Docker | файл образа и Compose разбираются в проверках, сам образ не собирался | собирайте на своей машине: `docker compose build` |
| Настоящие движки распознавания, синтез по образцу голоса (XTTS), языковая модель | демонстрационный движок, подменная команда синтеза, заглушка модели | качество и скорость — на своём оборудовании; см. главы [03](03-models.md) и [35](35-ai-analytics.md) |

## Сервер

| Ограничение | Обходной путь |
|---|---|
| Зависший внутри библиотеки вызов движка не прерывается: сторож снимает задание, отдаёт слот новому потоку и забывает экземпляр модели, но сам поток и его память живут до перезапуска | при повторяющемся `engine_hung` — драйвер видеокарты и перезапуск службы; дочерний процесс на воркер — в главе 33 |
| Одна модель — один экземпляр на видеокарте: второй видеокарте одна и та же модель нагрузку не делит | разные модели — на разных картах (`device: cuda:1` в пресете), либо второй сервер над общей базой |
| Близнецы в очереди (та же запись, те же настройки, тот же владелец) ждут идущего; близнец упал — второе задание распознаётся обычным порядком | дедупликация выключается параметром `deduplicate_jobs` |
| Кеш сводного отчёта аналитики — 30 с; изменения заданий на соседнем сервере над общей базой видны с этой задержкой | — |
| Цепочка хешей журнала доступа ловит правку и вырезанные строки, но не отрезанный хвост и не замену базы целиком | `audit_syslog` — копия строк во внешний журнал |
| Пароль копий шифрует только копию, уходящую командой «после копии»; копии в каталоге копий открыты | каталог копий — на отдельном диске с правами только для службы |
| Команда «после копии» задаётся только в файле настроек | так задумано: запуск программ на сервере — не право администратора приложения |

## Телефония

| Ограничение | Обходной путь |
|---|---|
| Разговор из нескольких ног сводится по `linkedid`: кто участвовал и сколько было переводов; какой сотрудник говорил на каком отрезке записи — нет (события `BlindTransfer`/`AttendedTransfer` не читаются) | разбор по сотрудникам — по ногам с собственной записью |
| События очередей — из `queue_log` (файл на сервере или строки от агента); события AMI `QueueCallerAbandon` не читаются | путь к `queue_log` у станции или агент на станции |
| Сверка «станция ↔ архив» не делается для AMI: независимого источника нет | для станций с AMI — журнал CDR как второй источник сверки |
| Самообновление агента — только по `auto_update` и только со сверкой sha256; докачки записей частями нет | обновление установщиком; большие записи — предел `max_upload_mb` |
| «Не записывать» и метка звонка — подпрограммами диалплана (`asrhub-norec`, `asrhub-tag`), не кодом в разговоре | код в разговоре — через `features.conf` (`applicationmap`) своими силами |

## Контроль качества

| Ограничение | Обходной путь |
|---|---|
| SIP — только UDP и открытый RTP | телефон сервера — в одной доверенной сети со станцией |
| Ответы — только кнопками; ветвления сценария, распознавания автоответчика и голосовых ответов нет | короткий сценарий из двух-трёх вопросов |
| Синтез по образцу голоса загружает модель на каждую фразу; образец один на сервер | готовые фразы — аудиозаписями в группе |
| Опрос — только обратным звонком; входящих на телефон сервера нет; звук опроса не сохраняется | — |
| Протокол SIP: ответ на re-INVITE предлагает оба кодека; 200 на re-INVITE не повторяется до ACK; ACK на 200 без `Authorization` | на Asterisk не мешает; на строгих SBC — проверьте пробным звонком |

## Веб-интерфейс

| Ограничение | Обходной путь |
|---|---|
| В политике содержимого остаётся `'unsafe-inline'` для скриптов: на нём держатся встроенные обработчики | экранирование подстановок — на месте; см. главу 33 |
| Сортировка по столбцу — не во всех таблицах; отбор и период раздела в адрес страницы не попадают | ссылка на карточку записи (`#jobs/<id>`) есть |
| Интерфейс только на русском | — |
