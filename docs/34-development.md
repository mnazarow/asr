# 34. Разработка: как устроен репозиторий, проверки и выпуск

Глава для того, кто правит код ASR Hub: где что лежит, как запустить сервер из клона, как гонять проверки и собирать руководство, что проверяют согласованность кода и документации и что делать при выпуске версии.

## Что где лежит

| Каталог | Что в нём |
|---|---|
| `server/asrhub/` | сервер: FastAPI (`api/`: сборка — `app.py`, лента событий — `event_hub.py`, прослойки — `middleware.py`, маршруты — `routes_*.py`), очередь (`job_queue.py`; выход наружу и проверка адресов — `outbound.py`), база SQLite (`db.py`; звонки и события станций — примесь `db_telephony.py`), движки (`engines/`), конвейер (`pipeline/`), телефония (`telephony/`), контроль качества (`qc/`), мониторинг (`monitoring/`), каталог параметров (`catalog/params/` — по файлу на группу) |
| `server/asrhub/web/` | интерфейс: одна страница без сборщика — `index.html`, `app.js`, `charts.js`, `styles.css` |
| `agent/` | агент станции (`asrhub-agent.py`, Python 3.6+ без зависимостей), его установщик и сценарий отправки диалплана `asrhub-dialplan` (POSIX sh + curl) |
| `scripts/` | установка, обновление, служба, проверка окружения — bash и PowerShell парами |
| `docker/` | образ и compose |
| `docs/` | руководство (главы `NN-имя.md`), генераторы и сборка в Word/PDF |
| `examples/` | короткие клиенты: каждый запускается сам и проверяется |
| `tests/` | проверки (pytest), в том числе браузерные (Playwright) |

## Сервер из клона

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements/dev.txt
ASRHUB_DATA_DIR=/tmp/asrhub-dev ASRHUB_MODEL=demo-simulator ASRHUB_ENGINE=demo \
  PYTHONPATH=server python -m asrhub --port 8080
```

Модель `demo-simulator` проходит весь путь задания без весов и видеокарты. Пароль первого запуска — в `/tmp/asrhub-dev/admin-password.txt` (или задайте `ASRHUB_ADMIN_PASSWORD`).

## Проверки

```bash
python -m pytest tests -q -p no:cacheprovider -rf                     # всё (больше часа)
python -m pytest tests -q -m "not web and not scripts and not drill and not slow"   # быстрый ярус
python -m pytest tests -q -n auto --dist loadfile                                  # параллельно (pytest-xdist)
python -m pytest tests/test_dialplan.py -q -k "сценарий"              # по имени
```

Метки ставит `tests/conftest.py` по имени файла: `web` — браузерные (`*_web.py`, `test_web_ui.py`, `test_manual.py`), `scripts` — установщики, служебные сценарии и образ, `drill` — сквозные прогоны разделов на наполненном архиве (`test_drill_*`), `slow` — полный цикл через очередь.

- **Браузер.** Браузерные проверки ищут Chromium (`PLAYWRIGHT_CHROMIUM` или `python -m playwright install chromium`); без него они пропускаются. `ASRHUB_REQUIRE_BROWSER=1` делает отсутствие браузера ошибкой — так в сборочном конвейере.
- **Подтверждения в интерфейсе** — окна, а не `confirm()`: в браузерной проверке ответ за человека даёт `отвечать(страница, True)` из `tests/drill_seed.py`, заданные вопросы — `заданные(страница)`.
- **Тема.** Интерфейс по умолчанию следует теме системы; браузерные проверки открывают страницы с `color_scheme="dark"`, чтобы снимки и контраст не зависели от машины.
- **Пароль администратора.** `conftest.py` ставит `ASRHUB_ADMIN_PASSWORD=admin123`: сотни проверок входят этой парой. Проверка случайного пароля сама снимает переменную.
- **Наполненный архив.** `tests/drill_seed.py` — `Архив` (база с заданиями, звонками, разбором), `поднять` (сервер в потоке на свободном порту), `Вкладка` (страница с проверкой, что в консоли нет ошибок). Вкладки одного файла делят браузер — у каждой свой контекст, — а `открыть(раздел)` ждёт признака `#content[data-ready]`, который `renderView` ставит, когда раздел отрисован и короткой выдержки на догрузку (с 3.1.38; прежде — полторы секунды наугад на каждый переход и запуск Chromium на каждую проверку).

## Линтеры

```bash
ruff check server tests agent/asrhub-agent.py examples
for f in server/asrhub/web/*.js; do node --check "$f"; done
npx eslint@9 --config eslint.config.mjs server/asrhub/web   # необъявленные имена, eval, мёртвый код
node --test tests/js/*.test.mjs                               # помощники интерфейса без браузера
shellcheck -S warning -s sh agent/asrhub-dialplan
shellcheck -S warning agent/install.sh
shellcheck -S error scripts/*.sh scripts/lib/*.sh
python -m mypy --ignore-missing-imports --follow-imports=silent server/asrhub agent/asrhub-agent.py
```

**Проверка типов — целиком.** С 3.1.38 весь сервер и агент проходят mypy без замечаний (в 3.1.35–3.1.37 чистые модули держались храповиком — списком `tests/mypy-clean.txt`, его больше нет); новое замечание останавливает конвейер и `tests/test_review_63.py`. Число из базы — `query_scalar(…)`, а не `query_one(…)["n"]`: строки может не быть. Проверка типов уже окупилась: в 3.1.35 она нашла, что whisper.cpp не получал квоту ядер контейнера (свойство вызывалось как функция, ошибку гасил запасной путь), в 3.1.36 — что метод чтения событий AMI был затенён одноимённым полем.

**Разметка в интерфейсе — шаблоном `` html`…` ``.** В `app.js` есть помеченный шаблон `html`, который экранирует каждую подстановку сам; готовая разметка вставляется только обёрнутой — вложенным `` html`…` ``, `raw(…)` (для того, что собрал сам код: `statusChip`, `act`) или массивом из них. Новые строки таблиц пишутся им; переведены строки «Очереди», «Результатов», журнала звонков, вкладки карточки записи и таблицы сотрудников «Голосовой аналитики» и отчётов за период. Строки, которые таблица обновляет на месте, — через `обновитьСтроки(тело, [[ключ, разметка], …])`: неизменившаяся строка остаётся тем же элементом, фокус в заменённой возвращается на ту же кнопку.

## Сборочный конвейер

`.github/workflows/ci.yml`: на каждый push и запрос на слияние — линтеры (ruff, mypy по всему серверу и агенту, ESLint, `node --test`, shellcheck) и быстрый ярус на Python 3.10 и 3.12; раз в сутки и по кнопке — полный набор с браузером (`ASRHUB_REQUIRE_BROWSER=1`) и покрытием (`--cov=asrhub`, отчёт `coverage.xml` — артефактом прогона) и сборка колеса с проверкой, что в него попали агент и руководство; там же — сборка образа Docker (профиль minimal, процессор) и проверка, что контейнер отвечает на `/api/health`.

`eslint.config.mjs` в корне — настройка ESLint 9 для `server/asrhub/web`: правила ловят ошибки, а не стиль. Проверка `test_eslint_config_is_clean_when_eslint_is_available` запускает его, если ESLint есть на машине (`eslint` в `PATH` или путь к нему в `ASRHUB_ESLINT`), и пропускается без него.

**Проход «роль × раздел × тема × ширина»** (`tests/test_review_61_web.py`): каждый раздел меню под администратором, пользователем и ключом «только чтение», в светлой и тёмной теме, на 1600 и 390 точках. Ловит исключения в скрипте, 5xx, пустой раздел и страницу шире экрана телефона.

## Согласованность кода и документации

Часть проверок следит не за поведением, а за тем, чтобы код и руководство не разошлись:

- **Маршруты.** Каждый маршрут API должен быть в справочнике (`docs/api-reference.md`, его собирает `docs/generate_api_full.py` с работающего сервера), а маршрут для администратора — в списке `ADMIN_ROUTES` генератора. Пути и параметры, упомянутые в главах, должны существовать.
- **Коды ошибок** из `errors.py` — в таблице главы 8.
- **Параметры** — только из каталога `catalog/params/` (файл своей группы: `server.py`, `telephony.py`, `llm.py`…; порядок групп — `ФАЙЛЫ_ГРУПП` в `__init__.py`): у каждого описание, рекомендация, примеры. Глава 4 и таблицы параметров собираются `docs/generate.py`.
- **Метрики** — из `monitoring/catalog.py` с описанием и порогом; глава 16 собирается тем же генератором, встроенные тревоги и правила Prometheus берутся из порогов.
- **Готовые файлы Asterisk** в главе 31 — те же, что отдаёт сервер: блоки `<!-- dialplan … -->` пересобирает `docs/generate.py`.
- **Ссылки и якоря** между главами разрешаются (якоря — как у GitHub).

После правки параметров, метрик, файлов диалплана или маршрутов:

```bash
PYTHONPATH=server python3 docs/generate.py
PYTHONPATH=server python -m asrhub --port 8099 &      # для справочника API
python3 docs/generate_api_full.py http://127.0.0.1:8099
```

## Руководство

- Главы — `docs/NN-имя.md`, номер главы берётся из имени файла. Новая глава — строка в `docs/00-README.md` и в списке `docs/assemble.py`.
- Раздел «Документация» интерфейса показывает те же файлы (`manual.py`); картинки — из `docs/images`.
- Снимки интерфейса: `PYTHONPATH=server python3 docs/make_screenshots.py` (на демонстрационном архиве, светлая тема): обзорные снимки разделов и снимки состояний — карточка записи и её вкладки, карточка модели, окно горячих клавиш, вкладки «АТС» и «Аналитики записей». Один снимок — именем: `… make_screenshots.py 14-job-card`.
- Word и PDF: `bash docs/build.sh` (нужен pandoc); `--screenshots` — сначала снять снимки заново. Предложения (`proposal-*.md`) и полный справочник API входят в документ приложениями.
