# Ревизия кода: что исправлено и что осталось

Раздел составлен по итогам полной проверки кода — сервера, подсистемы
мониторинга, скриптов установки и веб-интерфейса. Находки проверялись
запуском, а не чтением: гистограммы измерялись, аутентификация проверялась
запросами, скрипты прогонялись на макетах каталогов.

Здесь два списка: что уже исправлено и что осталось. Второй важнее — он
показывает, где система слабее, чем кажется по документации.

## Исправлено

### Установка и обслуживание

| Что было | Чем грозило |
|---|---|
| `install.sh` падал, когда все системные зависимости уже установлены: пустой массив + `grep` без совпадений + `pipefail` | Установка не проходила именно на укомплектованной машине. Самый разрушительный дефект: первое впечатление от продукта — откат и сообщение об ошибке |
| `uninstall.sh` без `--purge` сносил каталог данных на macOS | Потеря моделей, базы и результатов — при том что скрипт тут же писал «Данные сохранены». Каталог данных там лежит **внутри** каталога программы |
| `update.sh --rollback` вызывал `rsync --delete` поверх снимка, где лежит только код | Откат обновления уничтожал виртуальное окружение, а на macOS — и данные |
| `pkill -f "asrhub"` при удалении | Под удаление попадал любой процесс, у которого «asrhub» встречается в командной строке: редактор, `tail -f`, соседний шелл |
| Мастер установки перетирал `--profile`, `--engines`, `--models` | Ключи командной строки молча игнорировались |
| `xargs -r` и `grep -E '^\s*'` — расширения GNU | На macOS обновление обрывалось после резервной копии базы, а порт для проверки здоровья определялся неверно |
| `[[ "${WAS_RUNNING}" -eq 1 \|\| true ]]` — условие истинно всегда | Служба поднималась после обновления даже если её остановили намеренно |

### Безопасность

| Что было | Чем грозило |
|---|---|
| WebSocket `/ws` не проверял ключ вообще | Полный обход аутентификации: любой, кто дотянулся до порта, видел имена файлов, статусы и ошибки всех заданий в реальном времени |
| `DELETE /api/keys/{preview}` сопоставлял по `key.startswith(preview[:6])` | Все ключи начинаются с `ah_`, поэтому `DELETE /api/keys/a` отзывал первый попавшийся — в том числе действующий ключ администратора |
| Роль `user` не проверялась на владельца задания | Любой ключ с правом записи мог отменить, переставить и удалить чужое задание вместе с результатами |
| `POST /api/jobs/batch` не соблюдал `max_upload_mb` и не ограничивал число файлов | Ключ с ролью `user` забивал диск пакетом любого размера |
| Адрес webhook не проверялся и уходил в `urlopen` | Сервер обращался во внутреннюю сеть от своего имени: `file://` читал диск, `169.254.169.254` доставал учётные данные облака |
| Имя модели попадало в формат Prometheus без экранирования | В выгрузку метрик можно было вписать поддельные значения |
| Файл с автоматическим ключом создавался, а права выставлялись после | Окно, в котором ключ доступен на чтение всем |

### Потеря данных и работоспособности

| Что было | Чем грозило |
|---|---|
| `Settings.save()` не сохраняла ключи доступа, а файл переписывался целиком | Один вызов «Сохранить настройки» — и все ключи потеряны при следующем перезапуске. Ключи, созданные через API, вообще нигде не сохранялись |
| Миграции не умели добавлять колонки: `CREATE TABLE IF NOT EXISTS` не трогает существующую таблицу | После обновления база прошлой версии давала «no such column» на каждом запросе |
| Модель выгружалась из памяти посреди распознавания | `last_used` обновлялось только на границах, а простой в 900 секунд короче обычного совещания. То же при вытеснении из кеша |
| Один экземпляр движка работал из нескольких воркеров без блокировки | Модели PyTorch и CTranslate2 не рассчитаны на одновременный вызов |
| `cleanup()` удалял записи, но не файлы | Диск рос монотонно, хотя подсказка к ошибке «нет места» отправляет пользователя именно в эту очистку |

## Что осталось

Список отсортирован по тому, насколько вероятно вы на это наткнётесь.

### Стоит сделать в первую очередь

**1. Отмена задания не действует во время распознавания.**
Признак отмены проверяется на границах этапов, а внутри `engine.transcribe()`,
где проходит основное время, его нет. Кнопка «Отменить» на часовой записи
сработает не сразу, а `job_timeout_s` не прервёт зациклившийся движок.
Правильное решение — передавать признак отмены в движки и проверять его между
фрагментами; частичное — резать длинные записи на более мелкие куски.
*Трудоёмкость: несколько дней, по движку.*

**2. Гонка при отмене.** `cancel()` читает задание вне блокировки, а запись
идёт без условия на статус. Если воркер завершится между чтением и записью,
успешное задание получит статус «отменено» — или наоборот, отменённое станет
«готово» и уйдёт уведомление об успехе. Вероятность мала, но при большом
потоке отмен встретится. Лечится условием `WHERE status = ?` в обновлении.

**3. Уведомления создают поток на каждое задание.** Пула нет; при недоступном
получателе поток живёт около четырёх минут. Пакет из тысячи заданий с битым
адресом — тысяча потоков и столько же соединений с базой. Нужен ограниченный
пул рабочих потоков.

**4. Планировщик видит только 500 заданий.** Кандидаты выбираются по
приоритету, и лишь потом применяется политика. При очереди в тысячу заданий
политики `deadline` и `fair_share` работают на половине данных: срочное
задание с низким приоритетом не будет выбрано, пока не разгребётся верхушка.

**5. Кеш результатов почти не срабатывает.** `_find_cached` сравнивает хеши
среди 50 последних заданий в Python, хотя в `db.py` уже есть индексированный
`find_cached()` — и он не вызывается ниоткуда. При потоке больше 50 заданий
дедупликация просто не работает.

**6. Клон из кеша делит каталог результатов с оригиналом.** Удаление любого
из двух заданий уничтожает результаты второго, которое остаётся в базе как
«готово» с битой ссылкой.

### Стоит сделать

**7. Метрики в производных единицах.** `asrhub_ram_used_mb`,
`asrhub_disk_free_gb`, `asrhub_database_size_mb` — по соглашению Prometheus
должны быть в байтах, `asrhub_last_error_timestamp` — с суффиксом `_seconds`.
Переименование ломает существующие панели, поэтому делать это стоит одним
разом и с переходным периодом, когда отдаются оба имени.

**8. Метка `quantile` на обычных gauge.** `asrhub_rtf{quantile="p95"}` — это
не summary, и функции PromQL для summary к нему неприменимы. Правильнее либо
отдавать честные summary, либо переименовать метку.

**9. `set_concurrency` при уменьшении числа воркеров не убирает лишние
потоки.** Они крутятся вхолостую, а `status()` продолжает показывать их как
рабочие. Последовательность 2 → 8 → 2 оставляет восемь живых потоков.

**10. `recover()` ограничен тысячей заданий.** Если после аварии в состоянии
«выполняется» осталось больше, лишние зависают навсегда: их не выберет
планировщик и не удалит очистка.

**11. Устаревшие ответы в интерфейсе перезаписывают актуальные.** Быстрый
ввод в поиске: пришёл ответ на «alpha», затем на «beta», затем снова на
«alpha» — и таблица показывает не то, что в поле. Лечится `AbortController`.

**12. Ключ доступа попадает в адрес.** WebSocket и ссылки скачивания
передают ключ параметром, и он оседает в журнале сервера, в истории браузера
и в логах прокси. Для WebSocket альтернативы почти нет (заголовки в браузере
не задать), но одноразовый билет вместо ключа решил бы задачу.

**13. Узкий экран разъезжается.** Боковая панель фиксирована в 232 пикселя
без брейкпоинта: на телефоне контент сжимается до 158 пикселей, страница
едет горизонтально. Интерфейс рассчитан на настольный экран, и это стоит
либо починить, либо честно написать.

**14. Доступность.** Нет `role="dialog"` у модальных окон, фокус в них не
переводится, область загрузки файлов недостижима с клавиатуры, фокус не
виден на тёмной теме. Для внутреннего инструмента терпимо, для продукта — нет.

### Можно не спешить

**15. Проглоченные исключения.** Служебный цикл очереди целиком под
`except Exception` с уровнем `debug`: постоянно падающая очистка диска не
даст ни одной записи в журнале при штатном уровне INFO. Таких мест около
десяти; каждое стоит либо логировать заметнее, либо сузить перехват.

**16. Двойной учёт времени загрузки модели** исправлен в конвейере, но
`ProcessOutcome.rtf` по-прежнему складывает все стадии — включая подготовку
звука и выгрузку. Это завышает RTF относительно того, что показывают
производители моделей, и стоит либо считать честно, либо явно оговорить.

**17. `_mini_yaml` теряет списки верхнего уровня.** Запасной разборщик,
который включается без PyYAML, содержит недописанную ветку (`key if False
else None`). Списки в файле конфигурации при этом молча отбрасываются.

**18. StatsD отправляет всё с типом `|g`.** Счётчики теряют смысл; адрес
жёстко IPv4; имена меток отбрасываются, и значения разных меток склеиваются
по позиции.

**19. Docker не проверен сборкой.** Демон был недоступен там, где готовился
проект. Отдельно известно: `.dockerignore` лежит не в корне контекста и не
применяется; `ARG ACCEL` объявлен, но ни на что не влияет; том
`/var/lib/asrhub`, созданный установщиком от root с правами 0750, недоступен
контейнеру под uid 1000; nginx резолвит имя апстрима один раз при старте и
не знает про профиль `gpu`, где сервис называется иначе.

**20. Выравнивание MFA не проверено на реальных весах.** Логика раскладки
слов покрыта тестами, но сам вызов `mfa` не выполнялся: conda в среде сборки
не было.

## Чего в проекте нет и не планировалось

Чтобы не искать: **кластеризации** (несколько серверов не координируются),
**распознавания в реальном времени через WebSocket** (потоковый режим есть у
моделей, но наружу не выведен), **разграничения доступа сложнее трёх ролей**,
**синтеза речи**, **обучения и дообучения моделей**.

## Как это проверялось

- 146 автоматических тестов, включая регрессии на каждый исправленный дефект
  мониторинга.
- `ruff` без замечаний; `bash -n` и разбор PowerShell для всех скриптов.
- Проверки в браузере через Playwright: двойная отрисовка, утечка таймеров,
  экранирование пользовательских данных.
- Проверки запросами: обход аутентификации, отзыв чужого ключа, доступ к
  чужим заданиям, предел размера загрузки.
- Прогон скриптов на макетах каталогов: удаление на раскладке macOS, откат
  обновления, установка с полным набором зависимостей.

⚠️ Всё, что помечено «не проверено» (Docker, MFA), проверено не было — это
не осторожная формулировка, а прямое утверждение.
