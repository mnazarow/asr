# Сценарии настройки

Раздел не о том, что делает каждый параметр — это [04. Справочник параметров](04-parameters.md), — а о том, какие значения ставить под конкретную задачу и почему именно эти.

Каждый сценарий устроен одинаково: что за задача, что выбрать, чего ожидать, чем пожертвовали.

## Как настраивать вообще

Порядок, который экономит время:

1. **Возьмите ближайший пресет.** Он покрывает 80 % случаев и избавляет от подбора двух десятков связанных значений.
2. **Соберите десять типичных записей** с выверенным вручную эталонным текстом. Это единственный способ отличить улучшение от ощущения улучшения.
3. **Меняйте по одному параметру** и измеряйте. Три изменения сразу дадут результат, о причинах которого можно только гадать.
4. **Смотрите на разбор ошибок**, а не на итоговый WER: вставки, пропуски и замены лечатся разными средствами.
5. **Остановитесь.** Разница между «хорошо» и «идеально» обычно стоит десятикратного времени и не окупается.

## Протокол совещания

**Задача.** Запись встречи на 4–8 человек, конференц-микрофон, нужен читаемый текст с указанием говорящих.

```yaml
model: gigaam-v3-e2e-rnnt
language: ru
beam_size: 8
vad_enabled: true
vad_threshold: 0.40           # люди перебивают друг друга — не режем на полуслове
vad_min_silence_ms: 600
vad_speech_pad_ms: 300
audio_normalize: true         # микрофон один, говорящие на разном расстоянии
audio_highpass_hz: 80         # гул проектора и вентиляции
diarization_enabled: true
diarization_backend: pyannote
diarization_min_speakers: 2
diarization_max_speakers: 8
merge_short_segments: true
paragraph_mode: speaker
word_timestamps: true
output_formats: [docx, txt, json]
```

**Ожидать.** WER 5–8 % на разборчивой речи. Диаризация примерно удваивает время обработки.

**Чем пожертвовали.** Скоростью. Для протокола это правильный размен: перечитывать текст будут люди, и стоимость их времени выше стоимости машинного.

**Что помогает больше всего.** Не параметры, а микрофон. Запись с одного конференц-микрофона в большой комнате даёт WER втрое хуже, чем петличка на каждом. Если есть возможность писать по каналу на человека — `diarization_backend: channels`, и вопрос диаризации снимается совсем.

## Колл-центр

**Задача.** Телефонные разговоры, 8 кГц, узкая полоса, два собеседника, поток сотнями в день.

```yaml
model: tone-ru               # обучена на телефонии
language: ru
vad_enabled: true
vad_threshold: 0.35          # телефонный звук тише и глуше
audio_normalize: true
audio_sample_rate: 16000
diarization_backend: channels    # оператор и клиент в разных каналах
punctuation_enabled: true
itn_enabled: true                # номера заказов и суммы цифрами
glossary: "ваши термины и названия продуктов"
output_formats: [json, txt]
max_concurrent_jobs: 4
scheduling_policy: shortest_first
delete_source_after: true
```

**Ожидать.** WER 8–12 % на типичной телефонной записи. Это нормально: узкая полоса физически теряет часть информации, и лучше не будет ни у одной модели.

**Ключевое решение.** Разделение по каналам вместо нейросетевой диаризации. Если запись стереофоническая с разведёнными собеседниками, это точнее и практически бесплатно.

**Словарь замен окупается быстрее всего.** Названия ваших продуктов и тарифов модель не знает и никогда не угадает. Двадцать строк словаря дают больше, чем перебор всех остальных параметров.

## Субтитры к видео

**Задача.** Ролики и лекции, нужен файл SRT, который не стыдно наложить.

```yaml
model: gigaam-v3-e2e-rnnt
word_timestamps: true         # обязательно: без них разбивка «на глаз»
vad_enabled: true
vad_speech_pad_ms: 200
subtitle_max_line_width: 42   # две строки по 42 — предел читаемости
subtitle_max_lines: 2
subtitle_min_duration_s: 1.0
merge_short_segments: true
punctuation_enabled: true
output_formats: [srt, vtt, ass]
```

**Ожидать.** Готовый файл, требующий вычитки, но не переразбивки.

**Что важнее параметров.** Реплика должна помещаться в две строки и висеть не меньше секунды. Слишком короткие мелькают, слишком длинные не успевают смениться. `subtitle_max_line_width: 42` — проверенный компромисс для кириллицы.

## Массовая обработка архива

**Задача.** Десять тысяч файлов, нужно за выходные, качество «достаточное».

```yaml
model: gigaam-v3-ctc          # в 1.5–2 раза быстрее RNNT, потеря < 1 п.п.
beam_size: 1                  # жадный поиск: ещё почти вдвое быстрее
vad_enabled: true
vad_threshold: 0.5
compute_type: float16
batch_size: 16
priority: 20                  # не мешать интерактивной работе
max_concurrent_jobs: 2
scheduling_policy: shortest_first
deduplicate_jobs: true        # в архивах много дублей
delete_source_after: true
output_formats: [txt, json]
diarization_enabled: false    # дорого и обычно не нужно
punctuation_enabled: false
result_retention_days: 90
```

**Ожидать.** RTF около 0,05 на RTX 3060 — тысяча часов аудио за двое суток.

**Чем пожертвовали.** Примерно 1–2 процентными пунктами WER относительно максимума. Для поиска по архиву это несущественно; для публикации — нет.

**Отдельно.** Дедупликация в архивах даёт неожиданно много: одни и те же записи часто лежат в нескольких копиях под разными именами.

## Сервер без видеокарты

**Задача.** Обычный сервер, распознавание нужно, видеокарты нет и не будет.

```yaml
model: faster-whisper-small   # large на CPU — это часы на час аудио
engine: faster_whisper
device: cpu
compute_type: int8            # вдвое быстрее float32, качество почти то же
cpu_threads: 8                # по числу физических ядер
batch_size: 1
beam_size: 1
vad_enabled: true             # на CPU выигрыш от VAD самый заметный
vad_threshold: 0.5
max_concurrent_jobs: 1
job_timeout_s: 28800
```

**Ожидать.** RTF 0,8–1,5 на восьми ядрах: час записи за час-полтора.

**Что реально помогает на CPU.** Три вещи в порядке убывания: `int8`, VAD, модель поменьше. Всё остальное — доли процента.

**Альтернатива.** GigaAM в формате ONNX на CPU работает быстрее faster-whisper при лучшем качестве на русском. Если язык только русский — попробуйте `gigaam-v3-ctc` с движком `sherpa_onnx`.

## MacBook на Apple Silicon

```yaml
engine: whisper_cpp
model: whispercpp-large-v3-turbo-q5_0
device: mps
compute_type: auto
vad_enabled: true
batch_size: 1
max_concurrent_jobs: 1
```

**Ожидать.** RTF 0,15–0,3 на M2 Pro. От батареи заметно медленнее — Core ML снижает частоты ради энергосбережения.

**Почему whisper.cpp, а не PyTorch с MPS.** Core ML задействует Neural Engine, которого PyTorch не видит. Разница по энергопотреблению кратная — на ноутбуке это ощутимо.

**Чего не делать.** Не запускайте на Mac в Docker: доступа к Metal нет, всё считается на процессоре, и вы получите десятикратное замедление, не поняв почему.

## Реальное время

**Задача.** Показывать текст по ходу речи: живая расшифровка, субтитры трансляции.

```yaml
model: tone-ru                # или nemotron-asr-streaming-0.6b
streaming_chunk_ms: 300
streaming_latency_ms: 560
streaming_endpoint_silence_ms: 600
streaming_partial_results: true
vad_enabled: true
vad_backend: silero
beam_size: 1
diarization_enabled: false
punctuation_enabled: false
```

**Ожидать.** Задержка около секунды, качество на 2–4 процентных пункта хуже, чем при обработке файла целиком.

**Почему хуже.** Потоковая модель видит только прошлое; при обработке файла модель видит фразу целиком и может исправить начало по концу. Это ограничение архитектуры, а не настроек.

**Ошибка проектирования.** Не пытайтесь получить в реальном времени качество офлайн-обработки. Если текст нужен и мгновенно, и точно — показывайте потоковый результат сразу, а через минуту заменяйте его результатом полной обработки той же записи.

## Многоязычные записи

```yaml
model: parakeet-tdt-0.6b-v3
language: auto
task: transcribe
vad_enabled: true
batch_size: 8
compute_type: float16
```

**Ожидать.** 25 языков с автоопределением, очень высокая скорость.

⚠️ Автоопределение языка ошибается на коротких фрагментах и при переключении языка внутри записи. Если язык известен — задайте его явно, это почти всегда точнее.

**Перевод.** `task: translate` переводит речь на английский. Для перевода между другими парами — `canary-1b-v2`.

## Плохая запись

**Задача.** Диктофон в кармане, улица, эхо, шум.

```yaml
model: faster-whisper-large-v3    # устойчивее к шуму, чем лёгкие модели
audio_normalize: true
audio_highpass_hz: 100            # срезать гул и рокот
audio_denoise: true               # шумоподавление ffmpeg
vad_enabled: true
vad_threshold: 0.25               # тихую речь не потерять
vad_speech_pad_ms: 400
beam_size: 8
temperature_fallback: true        # каскад температур при неудаче
condition_on_previous_text: false # оборвать цепочки галлюцинаций
no_speech_threshold: 0.7
hallucination_filter: true
```

**Ожидать.** WER 20–40 %. Это честная оценка: если человеку приходится вслушиваться, модель тоже ошибётся.

**Чего ожидать не стоит.** Что настройки заменят запись. Разница между хорошим и плохим микрофоном больше, чем между лучшей и худшей моделью в каталоге.

## Юридическая и медицинская терминология

```yaml
model: gigaam-v3-e2e-rnnt
beam_size: 10
glossary: |
  довирительное управление -> доверительное управление
  ГК РФ
  субсидиарная ответственность
initial_prompt: "Заседание по делу о взыскании задолженности."   # для Whisper
punctuation_enabled: true
itn_enabled: true
include_confidence: true          # для вычитки: подсветить сомнительное
output_formats: [docx, json]
```

**Ключевое.** Словарь замен и — для семейства Whisper — `initial_prompt`. Модель, не знающая термина, подставит похожее по звучанию слово; словарь исправляет это детерминированно.

**Вычитка обязательна.** В юридическом и медицинском тексте одно неверно распознанное слово меняет смысл. Оценка уверенности помогает вычитывать выборочно: сомнительные места подсвечены.

## Диагностика и сравнение

**Задача.** Понять, что происходит, или честно сравнить модели.

```yaml
model: demo-simulator      # для проверки конвейера без весов
log_level: DEBUG
include_confidence: true
word_timestamps: true
output_formats: [json]
deduplicate_jobs: false    # иначе повторный прогон вернётся из кеша
```

Методика сравнения:

1. Десять записей с выверенным эталоном.
2. Прогон каждой модели с `deduplicate_jobs: false`.
3. Сравнение по WER, разбору ошибок, RTF и уверенности в разделе «Аналитика».

⚠️ `deduplicate_jobs: false` здесь обязателен: иначе повторный прогон того же файла с теми же настройками вернёт результат из кеша, и вы будете сравнивать кеш с кешем.

## Быстрая сводка

| Хотите | Меняйте |
|---|---|
| Быстрее без потери качества | VAD, `compute_type: float16`, модель CTC вместо RNNT |
| Быстрее любой ценой | `beam_size: 1`, модель поменьше, отключить постобработку |
| Точнее | `beam_size: 8–10`, модель побольше, нормализация звука, словарь |
| Меньше памяти | `batch_size` вниз, `compute_type: int8`, `max_concurrent_jobs: 1` |
| Убрать выдуманный текст | VAD, `condition_on_previous_text: false`, `no_speech_threshold` вверх |
| Говорящие по именам | `diarization_enabled`, а лучше — запись по каналу на человека |
| Готовый текст без правки | модель `e2e`, `punctuation_enabled`, `itn_enabled`, словарь |
