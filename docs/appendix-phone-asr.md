# Приложение. Разбор проектов phone_asr

В папке проекта лежат две ветки одного приложения — `phone_asr-add_alignment` и `phone_asr-add_gigaam`. Раздел отвечает на три вопроса: чем они отличаются друг от друга, чем отличаются от ASR Hub и что из них стоит перенести.

## Что это за приложение

`phone_asr` — сервис расшифровки телефонных разговоров с синтезом речи, построенный на **NVIDIA Triton Inference Server**. Три контейнера:

| Контейнер | Роль |
|---|---|
| `app` | FastAPI: приём звонков, загрузка аудио, оркестрация, отправка результата на callback |
| `asr_server` | Triton с четырьмя моделями: `faster_whisper`, `whisperx`, `pyannote`, `gigaam` |
| `tts_server` | Triton с F5-TTS, собранным под TensorRT-LLM |

Обмен между `app` и Triton — по gRPC, каждая модель обёрнута в Python backend (`model.py` + `config.pbtxt`). Около 5900 строк Python в каждой ветке.

Рабочий сценарий узкий и понятный: приходит `POST /process-call` со ссылками на файлы записи, ответ возвращается сразу (`202 Accepted`), обработка идёт в фоне, результат уходит на `target_url`. Стереозапись разводится по каналам на оператора и клиента; если запись моно — включается диаризация pyannote.

## Чем ветки отличаются друг от друга

Это **две параллельные ветки от общей базы**, а не последовательные версии. Отличий всего десять файлов.

### `add_gigaam` (файлы от 15.05.2026)

Добавляет GigaAM как модель Triton — четыре новых файла в `asr_server/models/gigaam/`:

```python
self._model = gigaam.load_model(
    self._config.model_name,       # v3_e2e_rnnt
    fp16_encoder=self._config.fp16_encoder,
    use_flash=self._config.use_flash,
    device=self._config.device,
)
...
segments = self._model.transcribe_longform(str(wav_path), min_duration=5, max_duration=8)
```

Сопутствующие изменения: `ASR_MODEL=gigaam` и `MODEL_NAME=gigaam` в compose, `INSTANCE_COUNT=2` вместо 1, проброс `HF_TOKEN` в контейнер, зависимость `gigaam[longform,torch]` из git. Зависимости `pyannote-audio` и `whisperx` **закомментированы** в `pyproject.toml` — при этом каталоги моделей `pyannote/` и `whisperx/` остались на месте. Ветка рабочая ровно для одного режима: GigaAM и ничего больше.

### `add_alignment` (файлы от 11.12.2025)

Добавляет **принудительное выравнивание через Montreal Forced Aligner** поверх faster-whisper. В Dockerfile появляются micromamba, пакет `montreal-forced-aligner` из conda-forge и загрузка русской акустической модели со словарём:

```dockerfile
RUN micromamba create -y -n mfa -c conda-forge montreal-forced-aligner
RUN mfa model download acoustic russian_mfa \
    && mfa model download dictionary russian_mfa
```

В `faster_whisper/1/model.py` — около 130 строк: текст Whisper подаётся в MFA как транскрипт, MFA возвращает TextGrid с пословными границами, границы разбираются обратно в сегменты, близкие сегменты склеиваются по `max_gap = 0.5`. Плюс сборка PyTorch из nightly-канала cu129 — ради поддержки Blackwell.

Обработка ошибок здесь сделана правильно: если MFA упал, берутся исходные тайминги Whisper.

```python
try:
    items = self._align_with_mfa(items, audio, mfa_dir)
except Exception:
    logger.exception("MFA alignment failed, keeping Whisper items")
```

### Сводка отличий

| | `add_alignment` | `add_gigaam` |
|---|---|---|
| Дата файлов | 11.12.2025 | 15.05.2026 |
| Модель по умолчанию | `faster_whisper` / `whisperx` | `gigaam` |
| Что добавлено | MFA-выравнивание, PyTorch cu129 (Blackwell) | GigaAM v3 e2e RNNT как модель Triton |
| Точность таймкодов | пословная, от MFA | посегментная, от `transcribe_longform` |
| Экземпляров Triton | 1 | 2 |
| pyannote / whisperx | в зависимостях | закомментированы |
| Размер образа | +2–3 ГБ (conda + MFA + модели) | без изменений |

Ветки **не объединены**: выравнивания MFA в ветке с GigaAM нет, GigaAM в ветке с выравниванием нет.

⚠️ **Токен Hugging Face зашит в исходники** в обеих ветках: `asr_server/models/pyannote/1/config.py`, строка 13, как значение по умолчанию для `HUGGINGFACE_ACCESS_TOKEN`, и второй раз в `misc/main.py`, строка 426. Токен действующий и виден любому, у кого есть доступ к репозиторию. Его стоит отозвать в настройках Hugging Face и заменить на чтение из окружения без значения по умолчанию.

## Чем phone_asr отличается от ASR Hub

Это разные по замыслу вещи, и сравнивать их «кто лучше» бессмысленно.

| | phone_asr | ASR Hub |
|---|---|---|
| Задача | один продакшен-сценарий: расшифровка звонков с callback | универсальный сервер: любые записи, любая из 72 моделей |
| Исполнение моделей | отдельный процесс Triton, gRPC | внутри процесса, реестр движков с кешем |
| Смена модели | пересборка образа и правка compose | значение в выпадающем списке |
| Моделей | 4, жёстко заданы | 72 в каталоге, 17 движков |
| Параметров | ~20 переменных окружения | 113 с описаниями, рекомендациями и примерами |
| Очередь | `BackgroundTasks` FastAPI + семафор | SQLite, приоритеты, 4 политики, повторы, переживает перезапуск |
| Интерфейс | нет, только API | веб-интерфейс из 10 разделов |
| Аналитика | нет | 12 разделов, WER/CER, экспорт в мониторинг |
| Установка | `make up`, только Docker с NVIDIA | скрипты для Linux, macOS, Windows; Docker и нативно |
| Обработка ошибок | try/except с логом | 24 типа с кодом, HTTP-статусом, признаком повтора и подсказкой |
| Диаризация | pyannote или разведение по каналам | то же плюс Sortformer и встроенная в модель |
| Синтез речи | есть (F5-TTS) | **нет** |
| Требования | NVIDIA GPU обязательно | GPU не обязателен |

Сильные стороны phone_asr, которых у ASR Hub нет:

- **Triton даёт динамическое батчирование и управление экземплярами моделей** — на потоке одинаковых коротких запросов это заметно эффективнее, чем последовательная обработка. Цена — отдельный процесс, gRPC и жёсткая привязка к NVIDIA.
- **Синтез речи.** ASR Hub занимается только распознаванием.
- **Точность пословных границ через MFA.** Модельные таймкоды — это оценка декодера; MFA выравнивает акустически и даёт заметно более точные границы слов. Для субтитров и дубляжа разница видна.
- **Схема «принял — ответил 202 — прислал на callback»** как основной режим, а не дополнение.

Сильные стороны ASR Hub, которых нет у phone_asr, перечислены в таблице выше; главные — сменяемость моделей без пересборки, очередь, переживающая перезапуск, и измеримость качества.

## Что перенесено и что стоит перенести

Два пункта из этого списка уже сделаны — они помечены. Остальные остаются предложениями.

**1. Принудительное выравнивание (MFA) — перенесено.** Самая ценная идея из ветки `add_alignment`. Легла в архитектуру ASR Hub как отдельный шаг конвейера между распознаванием и постобработкой: параметр `alignment_backend` (`none` / `mfa` / `whisperx`), откат на модельные таймкоды при любом сбое выравнивания. Цена та же, что у исходника, — установка MFA через conda, около 2–3 ГБ.

**2. `swap_sides` для телефонии.** Мелочь на три строки: в записях колл-центра каналы бывают перепутаны, и сейчас это лечится только перекодированием файла заранее.

**3. Разбиение длинной записи на части с `part` / `total_parts`.** В phone_asr это часть протокола callback. В ASR Hub есть группы заданий, но нет явной сборки одной записи из нескольких частей.

**4. `transcribe_longform` у GigaAM как необязательный режим.** ASR Hub сознательно режет длинное аудио сам, чтобы не тянуть pyannote и не требовать токена Hugging Face — это правильное умолчание. Но если у пользователя токен есть, режим `transcribe_longform` с `min_duration`/`max_duration` даёт своё качество сегментации, и его можно предложить как вариант.

**5. Полоса громкости — перенесена.** В phone_asr результат разговора несёт поле `waveforms`: запись режется на секундные интервалы, для каждого берётся средний модуль амплитуды, и получившаяся кривая уходит на callback вместе с текстом. Считается это в `app/src/routes/asr.py` (`generate_waveform`) и, чуть иначе оформленное, в `misc/main.py` (`generate_audio_waveform`, с полем `sample_rate`). Стереозапись даёт кривую на канал, монозапись перед расчётом делится диаризацией.

Идея дешёвая и полезная: расчёт занимает доли секунды и не зависит от модели, а по полосе видно строение разговора целиком. В ASR Hub перенесена с сохранением чисел до последнего знака — те же округления (время до трёх знаков, амплитуда до шести) и та же форма поля `waveforms` (массив JSON-строк, а не объектов), чтобы приёмник, написанный под phone_asr, работал без правок. Добавлено сверх исходного: настраиваемый шаг вместо жёсткой секунды, отдельный маршрут `GET /api/jobs/{id}/waveform`, разбивка по говорящим для монозаписи без принудительного деления на два канала и отрисовка в карточке задания с переходом к нужному месту расшифровки по щелчку.

**6. `words2numsrus` как лёгкая замена NeMo-text-processing.** ASR Hub использует NeMo для нормализации чисел; это тяжёлая зависимость. `words2numsrus` решает узкую задачу «двадцать пять» → «25» без установки NeMo — годится как запасной путь на слабой машине.

Чего переносить не стоит: Triton как слой исполнения. Он даёт выигрыш на однородном потоке, но ломает главное свойство ASR Hub — возможность сменить модель, не пересобирая ничего.
